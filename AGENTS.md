# AGENTS.md

Context for an AI coding agent — or any contributor — picking up this repo
cold. Humans: this doubles as orientation, but [README.md](README.md) is the
product pitch and [CONTRIBUTING.md](CONTRIBUTING.md) is the workflow. All
paths here are relative to the repository root.

---

## What Mnemos is

A local-first meeting-memory app: record, transcribe, and summarize meetings
on-device, organize what's learned into projects, and expose all of it to
external AI tools over MCP. Four processes, three languages:

- **`src-tauri/`** — Rust host (Tauri v2). Desktop shell, SQLite storage
  (`src/db/`), IPC commands (`src/commands/`, one file per feature area),
  and process supervision for the Python worker and Swift sidecar.
  `src/lib.rs` registers every command and event in one `specta_builder()`
  call — that single function is also what drives the generated TypeScript
  bindings.
- **`src-tauri/src/bin/mnemos-mcp-server/`** — a *second* binary in the
  same Cargo package (not a workspace, not a separate crate — see "The
  MCP server is a second binary" below). Opens its own read-only SQLite
  connection and speaks MCP over stdio.
- **`src-python/`** (`mnemos_worker/`) — long-lived subprocess of the Rust
  host. Owns transcription (`models/`) and memory extraction (`jobs/`).
  Speaks a framed JSON-RPC-like protocol over stdin/stdout
  (`protocol.py`, `dispatch.py`). **Never touches SQLite** — it returns
  structured results; the Rust host (`memory::extract_conversation`) is the
  only thing that writes them to storage.
- **`swift/mnemos-audio/`** — SwiftPM package, macOS-only, invoked as a
  subprocess for system + mic audio capture.
- **`src/`** — TanStack Router + React 19. `src/ipc/` is the only module
  allowed to import from generated `bindings/tauri.ts`; feature code imports
  from `@/ipc`. Routes in `src/routes/`, feature code in `src/features/`,
  shared UI in `src/components/`. **Chat lives in the app shell
  (`src/components/app/shell/RightRail.tsx` mounts `ChatPane`), not a
  route** — don't go looking for `/chat`.

## Non-negotiable rules

- **Never hand-edit `bindings/tauri.ts`.** Generated by `tauri-specta` from
  `lib.rs`; CI fails on drift (`cargo test specta_bindings`).
- **Never edit a file listed in `LOCKED_MIGRATIONS`** (`src-tauri/src/db/mod.rs`).
  A schema change after locking is always a new `NNN_*.sql` file. See
  "Migrations" below — this isn't a style preference, it's what stops a real
  user's already-applied database from refusing to start.
- **All SQLite access goes through `StorageService`** (`src-tauri/src/db/service.rs`).
  Nothing else opens a connection or writes raw SQL — including the Python
  worker, which is why it returns data rather than persisting it itself.
- **Comments explain why, not history.** No sprint/wave labels, no citations
  to documents outside this repo, no changelog-style comments ("this used to
  do X"). See [CONTRIBUTING.md](CONTRIBUTING.md) for the fuller version of
  this rule — it's enforced by convention, not tooling, so it only holds if
  everyone (agents especially) actually follows it.
- **Metrics properties are a closed enum, never a free string**
  (`src-tauri/src/metrics/properties.rs`'s `PropertyValue`). This is the
  actual privacy mechanism, not a lint preference: a call site that tries to
  pass a conversation title or transcript text as a metrics property fails
  to compile. If you're adding an event and reaching for `PropertyValue::String`,
  it doesn't exist — that's deliberate.

## The bar

These are mandates, not preferences. They apply to every change, by anyone,
human or agent. A change that violates one is incomplete, not merely
imperfect — and reviewers should say so plainly.

The reason the bar is written down: this is an open-source repo, and a large
share of the code arriving in it will be written by coding agents reading
this file. Whatever pattern is already here is the pattern that gets
multiplied. Sloppiness here doesn't stay one file's problem.

**One behavior, one implementation.** If two code paths can produce the same
outcome, they will eventually produce different ones. A new way to reach an
existing feature — another button, a menu item, a shortcut, an external
trigger — calls the path that already exists rather than re-deriving it.
When the existing path is awkward to reuse, fix the path; don't fork it.

**Derive state, don't mirror it.** Anything that displays state reads its
source of truth. The moment two places can independently decide what
something shows, they disagree — and the disagreement surfaces on an error
path nobody exercises by hand. Prefer one function that reads and renders
over setter calls sprinkled across every caller who has to remember.

**A state change and its consequences live together.** If mutating something
obliges the program to also update, clean up, or notify — do it at the
mutation, not further down a function where an early return, a `?`, or a
future edit can skip it. "The caller remembers" is not an invariant.

**Extract instead of copying.** Two surfaces rendering the same data the same
way share code. A comment reading "matches `<X>`'s formatting" is evidence
the extraction was skipped: prose cannot keep two implementations in sync,
and they drift the first time either is touched.

**Make invalid states unrepresentable where the language allows.** A closed
enum, a type that can't hold the wrong thing, a constructor that validates —
all beat a convention plus a code review. Reach for compile-time enforcement
first, a test second, a comment last. (`PropertyValue` above is the pattern.)

**Don't advertise what isn't built.** A type union, config key, or parameter
naming a capability that doesn't exist sends the next contributor — and
their agent — looking for a flow that was never written. Either build it,
or don't name it. Where a deliberate placeholder genuinely is the honest
state, say so at the definition, in a comment that explains what would fill
it in.

**Match the neighborhood.** Before introducing an idiom, check how the
surrounding code already solves that problem and follow it. A codebase with
one convention applied consistently is easier to work in than one where
every file makes a locally-optimal choice. If the existing convention is
genuinely wrong, change it everywhere in its own commit — don't leave two.

**Test the failure path.** The happy path usually gets exercised by hand
during development; error paths, cancellations, and partial failures don't.
Those are where the bugs that reach users live, and they're the tests worth
writing.

**Leave the diff small and legible.** No drive-by reformatting, no unrelated
renames, no scope the commit message doesn't mention. A reviewer should be
able to tell what changed and why without reconstructing your session.

## Things that look like bugs but aren't

**Starting a recording is a frontend-owned sequence, not a single command.**
`arm()` → `start_recording` → `markRecording()` → `subscribe_transcript` →
`subscribe_mic_level`, plus the gate that intercepts a Record click while a
previous conversation is still transcribing (`useRequestStartRecording` in
`src/features/active-conversation/useRecordingMutations.ts` is the only
place that decides whether to ask first). Calling the `start_recording`
Tauri command directly from somewhere else skips all of it: audio records
while the store still reads `idle`, so no session shows in the UI, the live
transcript never subscribes, and Stop has no session id to stop. Nothing
crashes — it quietly does the wrong thing. Anything outside the webview that
wants to start a recording should signal the frontend and let it drive;
closing the main window *hides* rather than destroys it
(`commands::recording::build_tray`'s `CloseRequested` handler calls
`api.prevent_close()` then `hide()`), so its listeners stay alive for the
life of the process. Reading backend state to *display* something needs no
such round trip.

**The MCP server binary's source directory is spelled with hyphens, not
underscores — `src/bin/mnemos-mcp-server/`, matching the `[[bin]] name` in
`Cargo.toml`.** This isn't cosmetic. Tauri's bundler infers a same-package
binary's expected filename from its `src/bin/<name>/` directory, not from
the `[[bin]] name` override — the two only need to agree for `cargo build`
to work, but `pnpm tauri build`'s bundling step silently looks for a binary
under the *directory* name and fails with `Failed to copy binary from
".../mnemos_mcp_server": ... does not exist` if they ever diverge. This
already happened once. If you ever touch this directory, keep the name
matching the Cargo bin name exactly.

**The migration connection runs with `foreign_keys(false)`, while the app's
real read/write pools run with `foreign_keys(true)`.** Not an oversight —
`PRAGMA foreign_keys` is a documented SQLite no-op once inside a
transaction, and sqlx wraps every migration in one, so a migration can't
toggle it itself. A rebuild-heavy migration (`DROP TABLE` + recreate while
other tables still hold FK references to it) fails with "database disk
image is malformed" under `foreign_keys=ON` and succeeds under `OFF` — this
was reproduced against a real on-disk database, not theorized. See the
comment directly above the connection in `src-tauri/src/db/mod.rs` before
"fixing" it.

**The data root is `~/Mnemos/` (or `%LOCALAPPDATA%\Mnemos` on Windows), not
the OS's sandboxed per-app data directory, and Windows deliberately uses
`%LOCALAPPDATA%` instead of `%USERPROFILE%`.** On managed Windows machines
with OneDrive Known-Folder-Redirection, a data root under `%USERPROFILE%`
would land inside a cloud-synced, Files-On-Demand folder — OneDrive's
placeholder/locking behavior is a known SQLite corruption risk.
`%LOCALAPPDATA%` is never redirection-synced. See `src-tauri/src/fs/paths.rs::data_root`.
One consequence worth knowing: an app *update* only ever replaces the
bundle at the OS's normal app-install location — it has no code path that
touches `~/Mnemos/` at all, so user data is structurally isolated from the
update mechanism, not just carefully avoided by convention.

**`RecordingRegistry` is keyed by session id even though v1 only ever has
one active recording.** Not preparing for multi-recording — it's so a stray
late command against an already-stopped session resolves to a clean
`NotFound` instead of a panic. Don't read the keyed-by-id shape as a hint
that concurrent recordings are supported; nothing else in the pipeline
assumes that.

## Migrations

`src-tauri/src/db/migrations/001_init.sql` is the entire schema today.
`LOCKED_MIGRATIONS` in `src-tauri/src/db/mod.rs` is empty pre-release —
nothing has shipped to a real user yet, so nothing needs protecting. The day
this project cuts its first tagged release, `001_init.sql`'s filename goes
into that list (and its hash into `src-tauri/tests/migration_lock.rs`'s
`EXPECTED_HASHES`) in the same commit — `.github/workflows/release.yml` has
a guard job that refuses to release at all if this was forgotten.

After locking, a schema change is always a new `NNN_*.sql` file, never an
edit to an existing one — sqlx checksums every applied migration on startup
and refuses to run if a locked file's content changed underneath it. Real
user data being unreachable because a comment got edited in a migration
file is not a hypothetical; it happened once during this project's own
development.

`db::init` also snapshots the database (`VACUUM INTO`, same mechanism
`StorageService::snapshot_backup_now` exposes manually) to
`~/Mnemos/backups/` immediately before a migration actually runs — but only
when the database already has real content and a migration is genuinely
pending, and it never fails startup even if the backup itself fails (a
missing safety net must never become a new way to fail to launch).

## Where tests live, and how to run them

```sh
pnpm test                                              # frontend, colocated *.test.ts(x)
cargo test --manifest-path src-tauri/Cargo.toml        # Rust: tests/ (integration) + inline #[cfg(test)]
cd src-python && pytest -q                              # Python worker
```

Four Rust integration tests are intentionally `#[ignore]`d — they need real
hardware or a live provider CLI (`MNEMOS_LIVE_RECORDING=1` + a real mic,
`MNEMOS_LIVE_CLAUDE=1` + a real `claude` CLI). Don't try to make them run by
default; they're gated for a reason, not forgotten.

Also see [README.md](README.md#checks) for lint/typecheck commands.
